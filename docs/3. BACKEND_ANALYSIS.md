# SafeShe Backend Analysis

This document provides an analysis of the core files constituting the SafeShe FastAPI Backend application (`/app`).

---

## 1. Core Application

### `app/main.py`
- **Purpose**: Initializes the FastAPI application, sets up CORS middleware, registers routers, and manages the application lifespan (startup/shutdown).
- **Imports**: `fastapi`, `uvicorn`, `app.config.settings`, `app.db.connection`, `app.api.v1.router`
- **Functions**:
  - `lifespan(app)`: Connects to MongoDB, initializes the DB, triggers automated audit, yields, then closes connections on shutdown.
  - `health_check()`: Returns system health status (`GET /health`).
- **Dependencies**: Depends heavily on Starlette routing and Uvicorn ASGI server.
- **Used By**: Executed directly by `python -m uvicorn app.main:app`.

### `app/auto_audit.py`
- **Purpose**: Diagnostic script that simulates frontend API requests against the running backend to verify contract compliance and Enum serialization.
- **Functions**:
  - `run_audit()`: Async function utilizing `httpx.AsyncClient` to hit multiple endpoints (Profile, Dashboard, Community, Journeys) and dumps the responses.
  - `trigger_audit()`: Dispatches the audit to a background thread to prevent blocking Uvicorn startup.
- **Writes To**: `audit_results.txt`

---

## 2. API Layer (`app/api`)

### `app/api/v1/router.py`
- **Purpose**: Consolidates all sub-routers (journeys, profile, settings, dashboard, community) under the `/api/v1` namespace.
- **Exports**: `api_router`

### `app/api/v1/journeys.py`
- **Purpose**: Exposes REST endpoints for the Journey lifecycle.
- **Endpoints**:
  - `POST /api/v1/journeys/`: Creates a journey. Returns `JourneyPlanResponse`.
  - `POST /api/v1/journeys/{id}/start`: Transitions state to active.
  - `GET /api/v1/journeys/{id}/monitor`: Exposes live telemetry for polling fallback.
- **Dependencies**: Injects `JourneyService` via `Depends()`.

---

## 3. Services Layer (`app/services`)

### `app/services/journey_service.py`
- **Purpose**: Core business logic orchestrating journey state mutations.
- **Classes**:
  - `JourneyService`:
    - `create_journey(user_id, data)`: Maps frontend string enums (e.g., `walking`) to PyMongo-compatible Enum objects (`TransportMode.WALK`). Persists to DB, delegates to Coordinator.
    - `start_journey(id)`, `complete_journey(id)`: Transitions MongoDB state.
- **Business Logic**: Normalizes input payloads. Ensures the data is DB-ready before passing Context objects to the `JourneyIntelligenceCoordinator`.

---

## 4. Repositories Layer (`app/repositories`)

### `app/repositories/base.py`
- **Purpose**: Generic PyMongo wrapper abstracting database interactions.
- **Classes**:
  - `BaseRepository`:
    - `__init__(collection_name)`
    - `create(document)`: Inserts a dict.
    - `get(id)`: Finds a document by ObjectId.
    - `update(id, data)`: `$set` operation.
- **Database Access**: Direct connection to MongoDB via `motor.motor_asyncio`.

### `app/repositories/journey_repo.py`
- **Purpose**: Extends `BaseRepository` with Journey-specific queries (e.g., fetching active journeys for a user).

---

## 5. Models & Schemas

### `app/models/journey.py`
- **Purpose**: Defines the MongoDB Document structure for Journeys.
- **Classes**:
  - `Journey` (Pydantic BaseModel): Represents the entire document.
  - `TransportMode`, `JourneyStateEnum`, `AlertStatus`: Python Enums. *(Note: Must inherit from `str` to successfully serialize into PyMongo).*

### `app/schemas/journey_schemas.py`
- **Purpose**: Defines Data Transfer Objects (DTOs) specifically enforcing the strict Frontend API contract.
- **Classes**:
  - `JourneyCreate`: Input validation.
  - `JourneyPlanResponse`, `LiveMonitorResponse`: Output formatting.

---

## 6. Intelligence Layer (`app/intelligence`)

### `app/intelligence/journey/coordinator.py`
- **Purpose**: The absolute Orchestrator for Agentic AI execution.
- **Classes**:
  - `JourneyIntelligenceCoordinator`:
    - `execute_pipeline(workflow_type, initial_context)`: Calls the WorkflowManager, runs Data Normalization, extracts Features, calls the ML Predictor, runs the Decision Engine, formats LLM context, invokes the Reasoning Tool, and packages the result.
    - `build_journey_plan_response(journey_id, request)`: Public interface called by `JourneyService`. Passes the true database `journey_id` down to the response builder to ensure endpoint continuity.

### `app/intelligence/response/builder.py`
- **Purpose**: Serializes output from the Intelligence Pipeline into valid Pydantic models.
- **Classes**:
  - `ResponseBuilder`:
    - `build_journey_plan()`: Replaces random mock UUIDs with the real PyMongo ObjectId.

---

## 7. AI Agents & Tools (`app/agents`, `app/tools`)

### `app/agents/workflow_manager.py`
- **Purpose**: Orchestrates multi-agent execution using DAG topological sorting.

### `app/tools/specialized/reasoning_tool.py`
- **Purpose**: Wraps LLM interactions into a standardized executable Tool. Parses the ML and contextual decisions to generate conversational AI recommendations ("Keep device accessible").

---

## 8. Error Handling

- **Global Handling**: Located in `app/api/handlers.py`.
- **Logic**: Catches `fastapi.exceptions.RequestValidationError` (422) and standard `Exception` (500). Wraps them in `{ "success": false, "error": { "message": "...", "code": "..." } }` to guarantee the frontend always receives the `StandardResponse` schema, preventing client-side crashes.
