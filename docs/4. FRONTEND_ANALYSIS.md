# SafeShe Frontend Analysis

This document provides a component-level analysis of the SafeShe React Application (`/frontend/src`).

---

## 1. Global Setup & Providers (`app/`)

### `layout.tsx`
- **Purpose**: Defines the Root HTML, configures fonts (Inter, Plus Jakarta Sans), and wraps the application in essential global providers.
- **Component Type**: Server Component
- **Child Components**: `ThemeProvider`, `ReactQueryProvider`
- **Styling**: Injects Tailwind global CSS variables.

### `middleware.ts`
- **Purpose**: Next.js edge middleware. Intercepts incoming requests to perform route-level protection (verifying JWT presence in cookies/headers) before allowing access to `/(dashboard)/*` routes.

---

## 2. API & Network Layer (`api/`)

### `client.ts`
- **Purpose**: Configures the base Axios instance (`axios.create()`).
- **Dependencies**: `axios`
- **Side Effects**: Attaches the `Authorization` header by reading from Zustand `useAuthStore` or local storage. Intercepts `401` responses to force a user logout.

### `services/journeyService.ts`
- **Purpose**: Abstracted functions encapsulating the HTTP requests to `/api/v1/journeys/`.
- **Functions**: `createJourney(data)`, `startJourney(id)`, `monitorJourney(id)`.

### `services/liveMonitorService.ts`
- **Purpose**: Dedicated service for fetching `LiveMonitorResponse` from the backend, originally polling `/api/v1/journeys/{id}/monitor`.

---

## 3. Global State (`store/`)

### `useJourneyStore.ts`
- **Purpose**: Zustand store managing the active journey's client-side state.
- **State**: `currentJourneyId`, `status` (planned, active, completed), `currentRouteGeometry`.
- **Hooks**: `setJourney()`, `clearJourney()`.

### `useAuthStore.ts`
- **Purpose**: Zustand store for authentication.
- **State**: `token`, `user`, `isAuthenticated`.

---

## 4. UI Components (`components/`)

### `ui/*` (Shadcn Components)
- **Purpose**: Accessible, unstyled generic UI primitives (Button, Card, Input, Dialog, Slider) integrated via Radix UI and styled via TailwindCSS using `class-variance-authority` (cva).
- **Dependencies**: `@base-ui/react`, `lucide-react`, `clsx`, `tailwind-merge`.

### `map/LiveMap.tsx`
- **Purpose**: The central visual element of the application. Renders the Mapbox/MapLibre GL map.
- **Component Type**: Client Component (`"use client"`)
- **Props**: `initialCoordinates`, `routeGeoJson`
- **Hooks**: `useRef` (map reference), `useEffect` (for updating layers when GeoJSON changes).
- **Dependencies**: `react-map-gl`, `maplibre-gl`.
- **Side Effects**: Connects to map tile servers using `NEXT_PUBLIC_MAP_KEY`.

### `map/JourneyMonitor.tsx`
- **Purpose**: An overlay panel sitting on top of `LiveMap` that displays AI telemetry.
- **State**: `telemetryData`, `isLoading`, `error`.
- **Hooks**: `useQuery` (Tanstack React Query) to poll `liveMonitorService`.
- **API Calls**: Polls `/api/v1/journeys/{id}/monitor` every few seconds.
- **Child Components**: Renders safety scores and AI text recommendations.

### `CommunityView.tsx` & `ReportAnomalyModal.tsx`
- **Purpose**: Interface for users to submit local danger reports (broken streetlights, etc.).
- **Component Type**: Client Component
- **Hooks**: `useForm` (React Hook Form), `zodResolver` (Zod).
- **API Calls**: POSTs payload to `/api/v1/community/`.
- **Side Effects**: Dispatches a Sonner toast (`toast.success`) upon successful submission.

### `DashboardView.tsx`
- **Purpose**: Renders the main dashboard cards displaying high-level AI status, health, and recent trips.
- **Component Type**: Client Component
- **Child Components**: Uses `Recharts` for plotting safety score trends.

---

## 5. Styling Strategy

- **TailwindCSS**: Entire application relies on utility classes.
- **Design System**: Strict adherence to curated design tokens (Inter font, sleek dark modes, glassmorphism on map overlays).
- **Animations**: `framer-motion` is utilized for smooth micro-interactions (e.g., expanding sidebar, fading in AI recommendations).
