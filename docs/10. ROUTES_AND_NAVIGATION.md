# SafeShe Routes & Navigation

This document maps the user navigation flow, frontend React routes, and their binding to backend API routes.

## 1. Frontend Routes (Next.js App Router)

The frontend is structured using Next.js 16+ App Router conventions (`/frontend/src/app`).

### Public Routes
- **`/` (Root)**
  - **Component**: `page.tsx`
  - **Purpose**: The main landing page for SafeShe. Contains marketing copy and login/signup CTAs.
- **`/login`**, **`/signup`** (Implied by components)
  - **Purpose**: Authentication gateways.

### Protected Routes (Route Group: `(dashboard)`)
These routes are visually wrapped in a common authenticated layout (sidebar/navbar) and require a valid JWT state managed by Zustand's `useAuthStore`.

- **`/dashboard`**
  - **Purpose**: The primary telemetry view showing `DashboardOverviewResponse` data (AI Status, Recent Activity, System Health).
- **`/live`**
  - **Purpose**: The interactive MapLibre map for Journey tracking. Features `LiveMap.tsx` and `JourneyMonitor.tsx`.
- **`/community`**
  - **Purpose**: A heatmap view of reported incidents and a form to submit new anomaly reports via `ReportAnomalyModal.tsx`.
- **`/profile`**
  - **Purpose**: User preferences and profile configuration.
- **`/settings`**
  - **Purpose**: Application settings (e.g., notification toggles).

## 2. Navigation Flow

### Typical User Journey
1. **Landing** `(/)`: User lands on the homepage.
2. **Authentication** `(/login)`: User logs in; Zustand `useAuthStore` saves the JWT.
3. **Redirect to Dashboard** `(/dashboard)`: `DashboardOverview` fetches from `GET /api/v1/dashboard/overview`.
4. **Start a Journey** `(/live)`: 
   - User inputs destination.
   - Frontend calls `POST /api/v1/journeys/` -> Transitions state to `PLANNED`.
   - User clicks "Start".
   - Frontend calls `POST /api/v1/journeys/{id}/start` -> Transitions state to `ACTIVE`.
   - `JourneyMonitor` component mounts and polls `GET /api/v1/journeys/{id}/monitor` or opens a WebSocket.
5. **Emergency (Global)**: User presses the SOS button located in the global authenticated layout.
   - Triggers `POST /api/v1/emergency/` or opens the `/api/v1/ws/emergency/` WebSocket.

| Frontend Route | Primary Component | Backend API Route | Method | Purpose |
|----------------|-------------------|-------------------|--------|---------|
| `/dashboard` | `DashboardView.tsx` | `/api/v1/dashboard/overview` | `GET` | Fetch top-level stats |
| `/live` | `LiveMap.tsx` | `/api/v1/journeys/` | `POST` | Create a new journey |

| `/settings` | `SettingsPage.tsx` | `/api/v1/settings/` | `GET` | Fetch user settings |

## 4. Protected Routes Logic

Protection is primarily handled on the client-side via React hooks.
- **Hook**: `useAuthStore()` provides `isAuthenticated`.
- **Logic**: If a user attempts to access `/(dashboard)/*` without a valid token, a `useEffect` redirect or Next.js middleware (e.g., `middleware.ts`) redirects them to `/login`.
- **API Security**: `axios` intercepts all requests and attaches `Authorization: Bearer {token}` to the headers. If the backend returns `401 Unauthorized`, the interceptor triggers a forced logout and redirects the user.
