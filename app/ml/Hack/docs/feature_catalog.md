# SafeShe ML Feature Catalog

This specification document outlines the complete list of features that will be present in the final Machine Learning dataset for SafeShe. 

It defines the exact inputs to the ML architecture designed in V2. **This is an architecture specification only. No implementation code is included.**

---

## Objective

The objective of this catalog is to establish a strict, frozen schema for the tabular datasets generated by the SafeShe Dataset Builder. Every feature defined here has a clear purpose, defined source, specific data type, and an agreed-upon engineering strategy to ensure consistency between offline model training and online route inference.

---

## 1. Segment Metadata

Metadata features uniquely identify the road segment and its spatial context. They are primarily used for joining data and identifying bottlenecks, rather than acting as predictive inputs.

| Feature Name | Description | Data Type | Source | Engineering Method | Expected Range | Missing Value Strategy | Normalization Strategy | Used During Training? | Used During Inference? |
|---|---|---|---|---|---|---|---|---|---|
| `segment_id` | Unique identifier for the road segment | `string` | Road Segment Generator | Deterministic hash of OSM way_id + offset | N/A | Drop record | None | No | Yes (for tracking) |
| `latitude` | Centroid latitude of the segment | `float32` | OSM | Geometric center calculation | -90 to 90 | Drop record | None | No | No |
| `longitude` | Centroid longitude of the segment | `float32` | OSM | Geometric center calculation | -180 to 180 | Drop record | None | No | No |
| `length_m` | Physical length of the segment | `float32` | OSM | Spatial path distance calculation | 10 to 250 | Drop record | Scale to meters | Yes (weights) | Yes (weights) |
| `district` | Canonical district name | `string` | Administrative Boundaries | Spatial point-in-polygon join | Categorical | Set to "Unknown" | Title case | No | No |
| `commissionerate_flag` | Indicates if segment falls in a commissionerate | `boolean` | Administrative Boundaries | Spatial boundary overlap | True / False | Default False | None | Yes | Yes |

## 2. Crime Features

Crime features supply the macro-level baseline risk (the "background prior"). The segment's safety score is shifted up or down from this baseline based on micro-level infrastructure.

**Fields extracted from `crime_score.csv`:**
Only the normalized `crime_score` and the respective district IDs are pulled. Aggregate rows are explicitly excluded. 

| Feature Name | Description | Data Type | Source | Engineering Method | Expected Range | Missing Value Strategy | Normalization Strategy | Used During Training? | Used During Inference? |
|---|---|---|---|---|---|---|---|---|---|
| `crime_score` | Background prior risk based on historical data | `float32` | Crime Loader (`crime_score.csv`) | Mapped via canonical district string | 0 to 100 | Fall back to nearest region | Min-Max scaling | Yes | Yes |

## 10. Derived Features

Higher-level engineered metrics created by combining multiple base features. These provide the ML model with rich, pre-computed spatial contexts.

| Feature Name | Description | Data Type | Source | Engineering Method | Expected Range | Missing Value Strategy | Normalization Strategy | Used During Training? | Used During Inference? |
|---|---|---|---|---|---|---|---|---|---|
| `commercial_density` | Intensity of commercial activity | `float32` | Feature Engineering | Sum of commercial POIs (malls, restaurants, banks) / buffer area | 0.0 to 1.0+ | Default 0.0 | None | Yes | Yes |
| `accessibility_score`| How easy it is to access the segment | `float32` | Feature Engineering | Combines `road_width`, `road_type`, and `sidewalk` | 0 to 100 | Default 50 | Min-Max scaling | Yes | Yes |
| `transit_density` | Proximity to public transportation | `float32` | Feature Engineering | Weighted sum of `bus_stop_count` and `metro_count` | 0.0 to 1.0+ | Default 0.0 | None | Yes | Yes |
| `emergency_accessibility`| Quickness of emergency response | `float32` | Feature Engineering | Inverse combination of `police_dist` and `hospital_dist` | 0 to 100 | Default 0 | Min-Max scaling | Yes | Yes |
| `walkability` | Suitability of the segment for pedestrians | `float32` | Feature Engineering | Combines `sidewalk`, `speed_limit` (inverse), and `crossing` | 0 to 100 | Default 50 | Min-Max scaling | Yes | Yes |
| `isolation_index` | Measure of how desolate a segment is | `float32` | Feature Engineering | Inverse of `population_density` + `commercial_density` | 0 to 100 | Default 50 | Min-Max scaling | Yes | Yes |
| `road_complexity` | Geometric and vehicular complexity | `float32` | Feature Engineering | Combines `lanes`, `junction`, `oneway`, and `road_curvature` | 0 to 100 | Default 20 | Min-Max scaling | Yes | Yes |
