# SafeShe Project Context

**Important:** This document is the permanent context document for all SafeShe AGY sessions. It should be the first file read to understand the project state, goals, and conventions before making changes.

---

## 1. Project Vision

- **What SafeShe is**: An AI-powered women's safety intelligence platform.
- **Primary objective**: To predict the safety level and crowd level of a location or route by synthesizing multiple diverse data sources (infrastructure, crime, environment, and crowd signals).
- **Long-term vision**: Deliver real-time, route-specific safety metrics that transcend static, high-level crime statistics. The platform will utilize synthetic data generation for prototyping micro-level features and will eventually integrate real data streams (like community reports and live CCTV mapping) for dynamic, highly localized safety intelligence.

---

## 2. Current Repository Structure

- `docs/`: Contains all architecture specifications, dataset schemas, feature engineering specs, audits, and this project context. It is the single source of truth for design decisions.

## 5. Crime System Summary

The crime system normalizes messy raw data into a strictly partitioned set of geographical contexts:
- **Canonical District Mapping**: 38 unified revenue districts in Tamil Nadu.
- **Commissionerates**: 8 major city police zones, separated from their parent districts to preserve urban granularity.
- **Railway Police**: Separated into specific railway divisions (e.g., Chennai, Trichy).
- **Special Units**: Non-geographic reporting cells (e.g., Cyber Cell) segregated.
- **Current Processed Outputs** (generated by `Crime Loader`):
  - `ml/datasets/processed/crime_score.csv` (Primary output; Revenue Districts only)
  - `ml/datasets/processed/crime_score_commissionerates.csv`
  - `ml/datasets/processed/crime_score_railway.csv`
  - `ml/datasets/processed/crime_score_special_units.csv`
*(National/State totals are explicitly excluded.)*

## 6. ML Vision

The project is actively transitioning its predictive scope:

**From:**  `District -> Safety`
**To:**  `Road Segment -> Safety`

District-level crime statistics are now treated as a **background prior (macro risk)** rather than the primary prediction target. The ML architecture will focus on generating micro-level predictions based on exact road configurations, infrastructure quality, and immediate surroundings.

## 8. Current Design Decisions

- **Architecture First**: All schemas, mapping tables, and feature engineering rules are strictly documented in Markdown before any Python code is written.
- **Pure Modular Pipeline**: Separation of concerns is enforced (Loaders -> Feature Engineering -> Label Generation -> Dataset Validation).
- **Reproducibility**: Pipeline outputs must be deterministic.
- **Clean Outputs**: Commissionerates, aggregates, and special units are strictly partitioned from the core dataset to prevent data pollution during ML training.
- **Single Source of Truth**: The `docs/` folder dictates behavior.

## 10. Coding Conventions

- **Language**: Python 3.10+
- **Typing**: Strict type hinting is enforced across the codebase.
- **Structure**: Utilize modular OOP patterns or `dataclasses` for state and configurations.
- **Separation of Logic**: Keep business logic (adapters/loaders) independent from configuration and mapping data.
- **Outputs**: Data pipelines must output deterministic artifacts strictly into `ml/datasets/processed/`.
- **Modifications**: Do NOT change dataset schemas or modify raw data. Always implement transformations via code in the engineering pipeline.
